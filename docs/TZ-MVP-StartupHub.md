## 1. Проблема и решение

**Проблема.** Начинающим стартапам, особенно студенческим, негде коротко и понятно показать свой проект. Людям, которые ищут интересные проекты (инвесторам, менторам, будущим участникам команды), неудобно искать их по разрозненным соцсетям и чатам.

**Решение.** StartupHub — веб-платформа, где основатель публикует профиль стартапа, а посетители просматривают каталог, ищут, фильтруют и открывают страницу стартапа с контактами.

**Фокус MVP** (из отчёта): публикация, просмотр, поиск и открытие профилей стартапов. Всё остальное идёт в backlog.

## 2. Роли пользователей

| Роль | Кто это | Что может |
|---|---|---|
| Гость | Незарегистрированный посетитель | Смотреть каталог, искать, фильтровать, открывать страницы стартапов |
| Основатель (Founder) | Зарегистрированный пользователь | Всё, что гость, плюс создание, редактирование, публикация и удаление **своих** стартапов, редактирование своего профиля |
| Администратор (Admin) | Модератор платформы | Всё, что основатель, плюс скрытие и удаление любого стартапа, блокировка пользователей |

> В MVP каждый зарегистрированный пользователь — Founder. Admin назначается вручную через seed или БД.

## 3. Границы MVP

### Входит в MVP
- Регистрация, вход, выход
- Профиль пользователя
- CRUD стартапа: черновик → опубликован
- Каталог опубликованных стартапов с пагинацией
- Поиск по названию и описанию
- Фильтры по индустрии и стадии, сортировка
- Страница стартапа
- Раздел «Мои стартапы»
- Простая админ-панель модерации
- Адаптивная вёрстка (desktop + mobile)

### Не входит в MVP (backlog)
- Сообщения и чат между пользователями
- Отдельная роль инвестора и заявки на инвестиции
- Лайки, избранное, комментарии, рейтинги
- Вход через Google/GitHub, подтверждение email, восстановление пароля по почте
- Уведомления
- Мультиязычность (MVP только на английском)
- Аналитика просмотров

## 4. Функциональные требования

## 7. API

Все ответы в JSON, ошибки в формате `{ "error": { "code": string, "message": string } }`.

| Метод | Endpoint | Доступ | Описание |
|---|---|---|---|
| POST | `/api/auth/register` | Гость | Регистрация + автоматический вход |
| POST | `/api/auth/login` | Гость | Вход, ставит cookie |
| POST | `/api/auth/logout` | Авторизованный | Выход, очищает cookie |
| GET | `/api/auth/me` | Авторизованный | Текущий пользователь |
| PATCH | `/api/users/me` | Авторизованный | Обновление профиля |
| GET | `/api/startups?q=&industry=&stage=&sort=&page=` | Все | Каталог (только опубликованные) |
| GET | `/api/startups/:slug` | Все* | Один стартап (*черновик — владелец и админ) |
| POST | `/api/startups` | Founder | Создание |
| PATCH | `/api/startups/:id` | Владелец, Admin | Редактирование |
| POST | `/api/startups/:id/publish` | Владелец | Опубликовать |
| POST | `/api/startups/:id/unpublish` | Владелец | Снять с публикации |
| DELETE | `/api/startups/:id` | Владелец, Admin | Удаление |
| GET | `/api/me/startups` | Founder | Мои стартапы (все статусы) |
| GET | `/api/admin/startups` | Admin | Все стартапы |
| POST | `/api/admin/startups/:id/hide` · `/unhide` | Admin | Модерация |
| GET | `/api/admin/users` | Admin | Пользователи |
| POST | `/api/admin/users/:id/block` · `/unblock` | Admin | Блокировка |

Ответ каталога: `{ items: Startup[], page, pageSize, total, totalPages }`.

Коды ошибок: `400` — валидация, `401` — не авторизован, `403` — нет прав, `404` — не найдено, `409` — email уже занят.

| ID | Требование |

| NFR-01 | Пароли хранятся только в виде хеша bcrypt (cost 10+) |

## 9. Стек и архитектура

| Слой | Технология | Почему |
|---|---|---|
| Фреймворк | **Next.js 15 (App Router) + TypeScript** | Фронт и API в одном репо, SSR для страниц стартапов, один деплой |
| UI | **Tailwind CSS + shadcn/ui** | Быстро собирается дизайн, готовые формы, диалоги и пагинация |
| Формы | React Hook Form + Zod | Одни и те же Zod-схемы на клиенте и на сервере |
| БД | **PostgreSQL 15+** | Локальный Postgres без Docker |
| ORM | **Prisma** | Схема, миграции и seed из коробки, типизация |
| Аутентификация | Своя: bcrypt + JWT (`jose`) в httpOnly-cookie + `middleware.ts` | Прозрачно и без внешних сервисов, легко объяснить на защите |
| Тесты | Vitest (unit) + Playwright (1–2 e2e-сценария) | Минимальная проверка auth и CRUD |
| Деплой (опционально) | Vercel + Neon/Supabase Postgres (free tier) | Бесплатная ссылка для демо |

**Разделение работы:** Alisher отвечает за `app/(pages)` и `components/`, Askar — за `app/api/`, `lib/` и `prisma/`, Kuanysh — за ТЗ, задачи и приёмку. Точка стыка — контракт API из раздела 7 и Zod-схемы в `lib/validation`.

## 11. Критерии приёмки MVP

MVP считается готовым, если по всем пунктам ниже результат положительный:

1. Гость открывает `/startups`, видит опубликованные стартапы, находит нужный через поиск и фильтр и открывает его страницу.
2. Новый пользователь регистрируется, создаёт стартап, видит его в `/dashboard` как `DRAFT`. В каталоге стартапа нет.
3. После «Publish» стартап появляется в каталоге. После «Unpublish» исчезает.
4. Пользователь A не может отредактировать или удалить стартап пользователя B: API возвращает `403`, даже при прямом запросе.
5. Admin скрывает стартап, и тот пропадает из каталога. Заблокированный пользователь не может войти.
6. Все формы показывают ошибки валидации по полям. Пустые поиски показывают пустое состояние.
7. Вёрстка корректна на ширине 360px и 1440px.
8. Проект поднимается с нуля по README, seed создаёт демо-данные и админа.
9. Все требования с приоритетом **M** выполнены.
